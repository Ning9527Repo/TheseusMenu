# TheseusMenu 0.2.6 Adaptive（源码版）

作者/维护者：半生年华。包名 `com.banshengnianhua.theseusmenu`，保持原包名与 1.0 包版本；源码修订号 0.2.6。

- 自动按触发视图（无有效触发视图时按菜单视图）的 UIKit 深浅色外观切换。浅色为白色，深色为灰黑 `#292929`（alpha 0.80，即透明 20%）；深色文字为白色，保留原生动作与点击区域。对原生 UIPasteControl 尝试通过前景色配置更新渲染槽位，实际效果须真机确认。
- 视觉高度固定为原生高度的 83%（48 pt → 39.84 pt），不再由粘贴槽位撑高。以原生文字中心定位背景，不对文字和粘贴槽位进行纵向变换，恢复 024 的整体胶囊裁切蒙版，统一遮住系统子图层露出的方形边缘；保留原生宽度、字号、点击区域。原生翻页 UIImageView 保留，圆底置于按钮内部、图标正下方，仅隐藏已识别的独立系统背景和细分隔线；遇到不支持的层级或空间不足时恢复原生按钮。菜单布局完成时立即更新，并保留已有异步刷新。0.2.6 在 025 基础上恢复完整胶囊遮罩，圆角半径为实际高度的一半；原生粘贴槽位仍不移动，39.84 pt 遮罩可能裁掉槽位边缘，实际文字显示需真机验证。
- 0.1.9：进入多任务界面的短暂 inactive 状态不再主动撤销可见菜单样式；实际进入后台仍清理。监听应用回前台、激活及场景激活，重新安装尚未安装的 hook，并在 0/50/160/350/800/1500 ms 内有限次扫描文本效果窗口与弱引用记录的菜单，恢复被重用或重建的菜单样式。不持续轮询。需真机验证。
- 不替换菜单动作；卸载样式时恢复原始文字颜色、箭头、变换等。无 Metal、Shader、背景截图或实时渲染。
- 记录 UIEditMenuInteraction 的配置 sourcePoint，跨窗口转换后根据菜单在触发点上方或下方，额外移动最多 10 pt。整体移动原生菜单及点击区域；在可用空间不足时减少偏移，无可靠触发点或触发点与菜单重叠时不移动。使用原生中心作为基准，不叠加偏移。
- 根据 iOS 17.1.1 真机日志，粘贴使用 55 × 40 pt 的 _UISlotView；024 将其向下平移 4 pt 并造成背景高度 42 pt。025/026 保留槽位原生位置，其他文字保持原生垂直基线；精确的槽位内部文字对齐仍须截图与真机确认。
- 遵循系统降低透明度设置，不改动该模式下的原生菜单。保留原版权许可证。

## 编译
本 ZIP 只包含已修改源码、构建工具与当前源码检查证据；旧版 DEB、dylib、缓存和旧构建证据已移除，不能直接安装 ZIP。需要 macOS + Xcode 生成新版 DEB。
macOS + Xcode：`make check`；RootHide: `make build ARCH=arm64e`；Rootless: `make build ARCH=arm64`。`make verify ARCH=arm64e` 验证 DEB。

## 专项诊断
`frida -U -N com.tencent.mqq -l TheseusMenuPasteTrace.js -o paste-debug.log`。适用 0.1.5–0.2.6（0.2.6 未真机验证）；0.1.6 起可输出 gap 状态。菜单显示后记录按钮索引、视图和图层几何、布局约束及触发点坐标。不读取文字、图片内容、剪贴板或聊天内容。请附菜单截图或粘贴按钮所在页/顺序。

仅源码检查、Swift 语法解析、JS 语法检查及独立几何模型测试；未进行 iOS SDK 类型检查、原生编译或真机验证。建议在 iOS 16/17 重点检查深浅切换、粘贴槽位文字颜色、翻页、点击与菜单出现/消失动画。

## 0.2.6 真机回归步骤
1. 打开文字编辑菜单，检查高度、原生宽度、背景与深浅色，比较文字与原生字形，检查长标签、图文组合和粘贴槽位是否裁切。
2. 上滑打开多任务界面后直接返回，重新长按文字；重复 5 次。
3. 切换到另一个应用再返回（含实际后台），重复长按、翻页、粘贴。
4. 确认菜单未逐次变矮、胶囊两端圆角未压扁、圆底内原生左右方向标均可见且方向正确，翻页点击正常。检查只有一个箭头及两个箭头的页面。若恢复原生，记录触发应用、iOS 版本及诊断日志。
